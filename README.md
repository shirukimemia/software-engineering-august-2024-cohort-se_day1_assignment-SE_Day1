#Part 1: Introduction to Software Engineering

Explain what software engineering is and discuss its importance in the technology industry.
- Software engineering is the systematic application of engineering principles to the design, development, testing, deployment, and maintenance of software systems. It involves problem-solving, coding, and project management to create efficient, reliable, and scalable software solutions.

Identify and describe at least three key milestones in the evolution of software engineering.
a) Birth of Software Engineering as a Discipline - a period when software projects were failing due to complexity, cost overruns, and poor quality.
b) Introduction of Software Development Life Cycle (SDLC) & Object-Oriented Programming (OOP) -  breaking development into phases like Requirements, Design, Implementation, Testing, Deployment, and Maintenance and introductionof the concept of classes and objects, making code more reusable and modular.
c) Agile Manifesto & the Rise of Agile Development - This is where introduction of concepts like Scrum, Kanban, and Extreme Programming (XP), emphasizing collaboration, customer feedback, and continuous delivery.

List and briefly explain the phases of the Software Development Life Cycle.
i) Planning	Define project goals & feasibility.	Project Plan & Requirements Doc.
ii) Design	Create system architecture & UI/UX.	Software Design Document (SDD).
iii) Implementation	Code the application.	A working software prototype.
iv) Testing	Identify and fix bugs.	Bug-free, stable software.
v) Deployment	Release the software to users.	Live, working software.
vi) Maintenance	Continuous improvements & fixes.

Compare and contrast the Waterfall and Agile methodologies. Provide examples of scenarios where each would be appropriate.

Waterfall - Linear & sequential.	Agile - Iterative & flexible.
Waterfall - Fixed phases (Requirement → Design → Development → Testing → Deployment). Agile - 	Continuous iterations (Sprints) with frequent updates.
Waterfall - Rigid; changes are difficult once development starts. Agile - 	Highly adaptable; changes can be made at any stage.
Waterfall - Testing is done after development is complete.	Agile - Continuous testing during development.
Waterfall - Customer Involvement is Limited involvement until final product delivery.	Agile - Frequent feedback from customers after each iteration.
Waterfall - Entire product is delivered at the end.	Agile - Small, working increments are delivered frequently.
Waterfall - Extensive documentation required upfront. Agile - 	Documentation is minimal, focusing more on working software.
Waterfall - Best for Projects with clear requirements and minimal expected changes. Agile - Best for Projects with evolving requirements and need for adaptability.
Waterfall - Used in Government & Regulatory Projects, Construction & Manufacturing Software, Stable & Well-Defined Projects 
Agile - Used in Startups & Product Development, Web & Software Applications, AI & Data Science Projects 

Describe the roles and responsibilities of a Software Developer, a Quality Assurance Engineer, and a Project Manager in a software engineering team.

Software Developer - Writes and maintains code, implements features, debugs issues.	e.g Coding a new checkout system for an e-commerce site.
QA Engineer -	Tests software, reports bugs, ensures quality standards.	e.g Identifying security vulnerabilities in a banking app.
Project Manager -	Plans, coordinates, and ensures project completion on time.	e.g Managing the development of a new SaaS platform.

Discuss the importance of Integrated Development Environments (IDEs) and Version Control Systems (VCS) in the software development process. Give examples of each.
IDES - Helps developers write and debug code efficiently.	VCS - Manages code versions and collaboration.
IDES - Features	Code editor, auto-completion, debugging, and integration with VCS.	VCS - Tracks changes, allows branching, merging, and collaboration.
IDES - Examples;	PyCharm, VS Code, IntelliJ IDEA, Eclipse.	VCS - Examples; Git, SVN, Mercurial.
IDES - Used in	Writing and managing code efficiently.	VCS - Used in Team collaboration and change tracking.

What are some common challenges faced by software engineers? Provide strategies to overcome these challenges.
Challenge - Debugging complex code. Solution - 	Use debugging tools, logs, divide & conquer.	
Challenge - Managing version control. Solution - Use Git branches, pull latest changes, resolve conflicts.	
Challenge - Keeping up with tech trends. Solution -	Follow tech blogs, take courses, contribute to open-source.	
Challenge - Tight deadlines & workload. Solution - 	Agile methods, breaking tasks, managing expectations.	
Challenge - Communication issues. Solution -	Use collaboration tools, shared documentation, clear tracking.	
Challenge - Security risks. Solution - Secure coding practices, authentication, security audits.	
Challenge - Writing scalable code. Solution -	Follow coding standards, write modular functions, code reviews.	


Explain the different types of testing (unit, integration, system, and acceptance) and their importance in software quality assurance.
Unit Testing -	Tests individual functions or components.	Ensures individual units work as expected.	Testing a function that calculates interest rates in a financial app.
Integration Testing -	Tests interactions between different modules or services.	Ensures components work together correctly.	Testing communication between a user-facing web app and a backend API.
System Testing -	Tests the entire system’s functionality.	Ensures overall system meets functional and non-functional requirements.	Simulating an e-commerce checkout process.
Acceptance Testing -	Tests if the system meets business requirements and is ready for deployment.	Confirms the system satisfies customer and stakeholder needs.	A new customer relationship management (CRM) system is tested by sales teams before launch.
